Support handover

A two-week trial for the shared inbox.

01Proposal

Assign one inbox owner each day. That person checks new requests, gives each one a named owner, and leaves a short handover before finishing.

The aim is to reduce missed requests without adding another meeting.

Scope

Run the trial for two weeks using the existing inbox and team rota. Keep the current escalation process. Do not change response targets until the trial has been reviewed.

What changes

  • One person is responsible for checking unassigned messages.
  • Every open request has an owner and a next action.
  • The outgoing owner leaves a handover in the shared log.

What to measure

Record unassigned requests at the end of each day, missed handovers, and time spent maintaining the log. Compare the results with the week before the trial.

02Daily routine

When Action Responsible
Start of day Check new and unassigned requests Inbox owner
During the day Assign requests and flag urgent items Inbox owner
Before finishing Record open items and the next action Inbox owner
Next morning Read the log and confirm receipt Incoming owner

Handover entry

Keep each entry short:

  1. Request: link to the original message.
  2. Owner: the person responsible for the reply.
  3. Next action: what needs to happen, and when.
  4. Blocker: include only if something is preventing progress.

If an urgent request has no owner, use the existing escalation process rather than waiting for the next handover.

03Decision needed

Before the trial

  • Confirm who can cover the inbox and name a backup for each day.
  • Choose a shared location for the handover log.
  • Agree a start date and a review date.

After two weeks

Review the log with the team. Continue if unassigned requests have fallen and the daily handover is manageable. Adjust the routine if the admin work outweighs the benefit.

Open questions

Does the rota need separate morning and afternoon cover? Who takes over when the named owner is absent? These need answers before the trial starts.
